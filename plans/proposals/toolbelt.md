# Toolbelt — proposal

> Status: **current decisions, 14 Nov 2026.** Decided: the name **Toolbelt**, no Track XP from equipping, the user bonus, the maker bonus and its 500 Ore cap per season, the significant-use gate, and up to two tool/projects per project. Still open: the reviewer checklist for the gate, and whether the Keystone tile stays. There is no seasonal pool. Ore values are for [Plan 02](../02-economy-and-rewards.md) to confirm.

## 1. What it is

The **Toolbelt** is where builders use other builders' finished, approved LOADOUT tool/projects in their own work. A tool/project is an accepted ship; "tool" is shorthand for it, and the rules say "tool/project".

## 2. What can be equipped

- Only accepted tool/projects, which must be open source (Plan 01).
- Any track. Cross-track use counts.

## 3. Equipping

- A builder can equip **up to two** Toolbelt tool/projects into one of their own tool/projects.
- Each equip must have **significant impact**: the tool is used in a core part of the project, not a demo, and the use note names where (a file or feature).
- There is no cap across all of a builder's projects.
- Equipping gives **no Track XP**.

## 4. The significant-use gate

A use is paid only when the team confirms it passed the gate, using the project's existing journal:

1. The project that equips the tool has at least **25 approved hours** (confirmed 14 Nov 2026: the equipping project, not the maker's).
2. The tool is used in a core part of the project, named in the use note.
3. The builder's journal shows the tool doing real work in the project. There is no minimum time period.
4. The reviewer confirms the journal entries show real use, not a passing mention.

The reviewer checks the gate with the same checklist each time (the checklist is still to be written).

## 5. Evidence: the journal

There are no separate checkpoints. Builders mention their tool use in the project journal they already keep, as part of the normal journal rule. The reviewer uses those entries as the evidence for the gate. A journal entry that only names the tool doesn't count; it needs to say what the tool did in the work.

## 6. Rewards

- **User:** **50 Ore once per tool/project**, paid when the gate is passed.
- **Maker:** **10 Ore per verified user** who passes the gate, paid as each user passes it. Capped at **500 Ore per tool/project per season**.
- **Track XP:** none from equipping. Track XP is 10 per approved hour, as set on 14 Nov.
- **Flagship:** a separate standout award, decided by the reviewer. See [rewards-and-recognition.md](rewards-and-recognition.md).

Removed on 14 Nov (the six-week rule and checkpoints too): Usage Milestone bonuses, the "Field-tested" and "Widely used" badges, the per-builder equip cap, and per-checkpoint Ore. The Keystone tile is kept as a recognition for the most-equipped tool/project in each track, unless you want it removed too.

## 8. Privacy and safety (ages 13–18)

- Handles only, no real names, schools or locations.
- Equips and journal entries about tool use are public, like journals. Reviewer-only evidence is allowed where the existing attachment rule applies.
- No direct messages in v1.
- A maker can block a builder from equipping their tool/project.

## 9. Open items

1. The reviewer's significant-use checklist, including what counts as a journal entry about tool use.
2. Whether the Keystone tile stays.
